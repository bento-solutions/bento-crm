# Bento mobile app (Capacitor)

The staff app for Android and iOS is the same Angular build, wrapped by [Capacitor](https://capacitorjs.com) 8.
The configuration is in `capacitor.config.ts` (app id `ma.bento.app`, name `Bento`, web assets from
`dist/app/browser`). The native projects (`android/`, `ios/`) are not in the repository yet: they are
generated once on a machine that has the platform SDKs.

What the app adds on a phone (all of it is a no-op in a browser, see `NativeService`):

- **Take a photo** on the documents inbox: the camera photographs a supplier invoice and uploads it like
  any other file, so the AI reader extracts it and it waits under "To check".
- **Push notifications**: after sign-in the phone asks for permission, registers with Firebase Cloud
  Messaging (Android) or APNs through Firebase (iOS) and sends its token to `POST /devices`. Sign-out
  removes it (`DELETE /devices`). Tapping a notification opens the related record (a checklist, the tax
  calendar, the documents inbox…).

## Requirements

- Node 22+ and the project's dependencies (`npm ci`).
- Android: Android Studio (with an SDK and a JDK 21).
- iOS: a Mac with Xcode 16+ and CocoaPods or Swift Package Manager.

## Adding the platforms (once)

```bash
npm ci
npx ng build
npx cap add android
npx cap add ios
```

Commit the generated `android/` and `ios/` folders.

Then, for every change to the web app:

```bash
npm run cap:sync      # build, then copy the web assets and plugins into both platforms
npm run cap:android   # build, sync and open Android Studio
npm run cap:ios       # build, sync and open Xcode
```

Builds point at the API of the Angular configuration used (`src/environments/`); use
`npx ng build --configuration dev` before `npx cap sync` for the dev backend.

### Camera permission

- Android: nothing to add, the Camera plugin declares what it needs.
- iOS: add to `ios/App/App/Info.plist`:
  - `NSCameraUsageDescription`: "Bento uses the camera to photograph supplier invoices."
  - `NSPhotoLibraryUsageDescription` and `NSPhotoLibraryAddUsageDescription` (required by the plugin).

## Push notifications (Firebase)

1. Create a Firebase project and add an **Android app** with package name `ma.bento.app`. Download
   `google-services.json` and put it in `android/app/`. (The Gradle project generated by Capacitor
   applies the Google services plugin when the file is present.)
2. Add an **iOS app** with bundle id `ma.bento.app`. Download `GoogleService-Info.plist` into
   `ios/App/App/` (add it to the target in Xcode). In the Firebase console, under *Project settings →
   Cloud Messaging*, upload an **APNs authentication key** (`.p8`, created in the Apple Developer account
   under *Keys*, with its Key ID and Team ID). In Xcode, enable the *Push Notifications* capability and
   *Background Modes → Remote notifications*. Follow the Capacitor push guide to forward the APNs token to
   Firebase Messaging in `AppDelegate.swift`, so the token the app receives is an FCM token.
3. Server: create a Firebase **service account** key (*Project settings → Service accounts → Generate new
   private key*) and point the API at it:

   ```
   app.push.fcm.service-account-file=/run/secrets/firebase-service-account.json
   ```

   (or the environment variable `APP_PUSH_FCM_SERVICE_ACCOUNT_FILE`). Without it the API stores device
   tokens but sends no pushes; `GET /devices/push-status` tells which.

## Server settings for the app

The app's web view calls the API from its own origin: `https://localhost` on Android and
`capacitor://localhost` on iOS. Both must be in the API's allowed CORS origins
(`CORS_ALLOWED_ORIGINS`), otherwise every request from the app is refused.
